# postgres-sample — DDL de ejemplo (contrato `DDL_DIR`)

Esta carpeta es un **ejemplo funcional** de lo que el toolkit espera en `DDL_DIR`.
No es una base real: sirve para **ver el contrato en concreto** y para probar el
flujo `--schema` de punta a punta sin tener que traer tu propio esquema.

> El DDL de tu base real **no se versiona** en este repo (es específico de cada base
> y el toolkit es agnóstico). Este sample sí se versiona porque es genérico y didáctico.

## Qué contiene

`sample_shop/` — una tiendita mínima (categorías, productos, clientes, pedidos,
líneas de pedido y tokens de API), con los **cuatro archivos** del contrato:

| Archivo | Qué demuestra |
|---|---|
| `00_init.sql` | extensión `pgcrypto` + una colación ICU *case-insensitive* (análogo `*_CI_AS`) |
| `01_schema.sql` | tablas base con PK identity (`GENERATED BY DEFAULT AS IDENTITY`) y una tabla con **PK `uuid`** |
| `02_constraints_indexes.sql` | PK / FK / índices + aplicación de la colación al email |
| `03_views.sql` | dos vistas (quedan **fuera** de la validación) |

Los tipos están elegidos para **ejercitar cada chequeo de `--validate`**:

- `integer` / `numeric(12,2)` → **suma exacta** (Price, Total, Quantity, UnitPrice…).
- `double precision` (Weight, Discount) → **excluida** de sumas (aproximada).
- `varchar` / `text` (Name, Email, Notes, Token…) → **paridad de strings** fila a fila.
- `ApiToken` con **PK `uuid`** → fuerza la estrategia *match por dict* de la paridad.
- `boolean` / `timestamptz` / `jsonb` → se copian intactos (no se suman).

## Cómo probarlo

Apunta `DDL_DIR` a la base de ejemplo en tu `migration/.env`:

```
DDL_DIR=../postgres-sample/sample_shop
```

y crea el esquema destino (DROP+CREATE de la base PG + DDL `00..03`):

```bash
cd migration
.venv/bin/python migrate.py --schema --fresh     # Windows: .venv\Scripts\python
```

Eso deja la base PostgreSQL con las 6 tablas y las 2 vistas listas. Para una
migración real necesitarías un **origen MSSQL con el mismo esquema** al que apuntar
`--data`/`--validate`; este sample cubre el lado **destino** del contrato.
