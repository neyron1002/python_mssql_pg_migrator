Migra de MS SQL Server a PostgreSQL

Toolkit en Python para copiar los datos de cualquier base MSSQL a PostgreSQL 18 y verificar, tabla a tabla, que todo migró intacto. Sin psql, sqlcmd ni pgloader: solo psycopg + pyodbc.

¿Por qué usarlo?

Copiar datos es fácil; garantizar que migraron bien, no. Esto hace ambas cosas.

🐍

Cero CLIs externas

Solo Python y dos librerías. Nada de psql, bcp, pgloader ni CSVs intermedios.

🧩

Agnóstico a la base

Es schema-driven: descubre el plan introspeccionando el esquema destino. Tú traes tu DDL; funciona con cualquier esquema.

✅

Integridad verificable

Valida conteos, sumas numéricas exactas, rango de PK y paridad de strings byte a byte (detecta mojibake y truncamiento).

🔑

PK preservados 1:1

Inserta los identificadores con su valor original y re-sincroniza las secuencias para que la app siga sin colisiones.

📦

Escaping seguro

Usa el protocolo COPY de psycopg: texto libre y blobs JSON viajan intactos, verificado con round-trip byte a byte.

⏱️

Cronómetro incorporado

Tiempo por etapa y por tabla, con un “RESUMEN DE TIEMPOS” al final de cada corrida.

Cómo funciona

Una sola CLI (migrate.py) orquesta tres etapas.

1
--schema — crea el esquema

Crea la base PostgreSQL (locale ICU) y aplica tu DDL (00..03.sql) vía psycopg.

2
--data — copia los datos

Copia MSSQL→PG con COPY, preservando PK, con las FK deshabilitadas durante la carga, y re-sincroniza las secuencias.

3
--validate — verifica

Compara origen vs destino (conteos, sumas, rango de PK, paridad de strings) y sale con 0 (íntegra) o 1 (falla).

Empezar en 3 pasos

Desde la carpeta migration/ del repo.

# 1) entorno + dependencias
python -m venv .venv
.venv/bin/pip install -r requirements.txt

# 2) configuracion: credenciales de origen/destino + DDL_DIR
cp .env.example .env        # edita el .env

# 3) verifica prerrequisitos y migra
.venv/bin/python check_requirements.py --connect
.venv/bin/python migrate.py --all      # esquema + datos + validacion

Tú traes el DDL

El toolkit no incluye ningún esquema. Apunta DDL_DIR a una carpeta con estos cuatro archivos, que se aplican en orden:

ArchivoContenido
00_init.sqlInicialización previa (extensiones, colaciones, tipos). Puede ir vacío.
01_schema.sqlTablas base (columnas identity como GENERATED BY DEFAULT AS IDENTITY para preservar PK).
02_constraints_indexes.sqlPK / FK / índices / constraints.
03_views.sqlVistas (no llevan datos; quedan fuera de la validación).
